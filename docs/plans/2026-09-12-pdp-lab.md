# PDP Lab Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Catalogue, circle and explain the on-page features of 13 product-detail
pages from non-pickleball verticals, exposed under a brand-new `/pdp` menu that
leaves every existing page and number untouched.

**Architecture:** Full data isolation. A second SQLite file (`db/pdp.db`) built
from the *same* `scripts/schema.sql`, fed by the *same* scripts via three new
environment overrides (`CATALOG_DB`, `CATALOG_MARKDOWN`, `CATALOG_SHOTS`). The
web app gets a parallel read-only module (`web/lib/pdp-db.ts`) and routes under
`/pdp`. Nothing in `web/lib/db.ts` or any existing route changes behaviour.

**Tech Stack:** Python 3 + self-hosted Firecrawl + crawl4ai + Playwright/Pillow
for annotation; Next.js 15 App Router + `node:sqlite` for the UI.

---

## Why a second database (the constraint that shapes everything)

`web/lib/db.ts` queries `sites`, `features`, `pages` and `annotations` with **no
site filter**. `getStats()` is `COUNT(*) FROM sites`. So loading 13 new sites
into `db/features.db` would change the Overview totals, add 13 rows to
`/features`, `/screens`, `/search`, and pollute the `/compare` and `/gaps`
canonical taxonomy — which is exactly the "don't disturb the existing pages"
failure mode.

A second DB file also resolves three collisions for free:

| Collision | Why it happens | Resolved by |
|---|---|---|
| `luzzpickleball.com` already in the catalog | it is URL #8 in this batch | separate `db/pdp.db`; `sites.domain` is UNIQUE per file |
| `data/markdown/luzzpickleball.com/` overwrite | `markdown_path_for()` keys on domain only | `CATALOG_MARKDOWN=data/pdp/markdown` |
| `data/screenshots/luzzpickleball.com/*.png` overwrite | `SHOT_DIR / domain` | `CATALOG_SHOTS=data/screenshots/pdp` |

Screenshots deliberately land **inside** `data/screenshots/` so
`web/app/api/shot/route.ts` keeps working with zero changes — its `ALLOWED`
guard resolves to `data/screenshots` and `data/screenshots/pdp/...` is inside it.

## Task 1 — Make the three data paths overridable

**Files:**
- Modify: `scripts/db.py:10-16`
- Modify: `scripts/annotate.py:25`

**Step 1: add the env overrides to `scripts/db.py`**

```python
import os
ROOT = Path(__file__).resolve().parent.parent
DB_PATH = Path(os.environ.get("CATALOG_DB") or ROOT / "db" / "features.db")
SCHEMA_PATH = ROOT / "scripts" / "schema.sql"
MARKDOWN_DIR = Path(os.environ.get("CATALOG_MARKDOWN") or ROOT / "data" / "markdown")
SHOT_DIR = Path(os.environ.get("CATALOG_SHOTS") or ROOT / "data" / "screenshots")
```

Relative override values resolve against `ROOT`, so `CATALOG_DB=db/pdp.db`
works from any cwd:

```python
if not DB_PATH.is_absolute():        DB_PATH = ROOT / DB_PATH
if not MARKDOWN_DIR.is_absolute():   MARKDOWN_DIR = ROOT / MARKDOWN_DIR
if not SHOT_DIR.is_absolute():       SHOT_DIR = ROOT / SHOT_DIR
```

**Step 2: point `annotate.py` at it**

Replace `SHOT_DIR = db.ROOT / "data" / "screenshots"` with `SHOT_DIR = db.SHOT_DIR`.

**Step 3: prove the default is unchanged**

```powershell
.venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'scripts');import db;print(db.DB_PATH, db.MARKDOWN_DIR, db.SHOT_DIR)"
```
Expected: the three original paths, `db\features.db` among them.

**Step 4: prove the override works**

## Task 3 — Build the shared canonical vocabulary BEFORE extracting

**Files:** Create `data/pdp/canonical.md`

Comparison in this system keys on the canonical slug. Thirteen independent
extraction agents will otherwise invent "Subscribe & Save", "Subscription
discount" and "Sub-and-save pricing" for one concept and manufacture three fake
gaps (`REQUIREMENTS.md` §3). So the vocabulary is written **first**, from what a
PDP actually contains, and every agent must draw from it.

Seed list (PDP-native, vertical-neutral), grouped:

- **conversion** — Subscribe & Save, One-Time vs Subscription Toggle, Quantity
  Tiered Discount, Bundle Upsell, Sticky Add-to-Cart, Free Shipping Threshold,
  Discount Code Field, Buy-Now Express Checkout, Cart Drawer Upsell, Gift Option
- **payments** — Buy Now Pay Later, Wallet Express Buttons, Multi-Currency Pricing
- **social proof** — Star Rating Summary, Customer Reviews, Verified Buyer Badge,
  Review Photos, Review Filters/Search, Q&A, Press Logos, Influencer/UGC Rail,
  Recent-Purchase Notification, Aggregate Customer Count
- **product info** — Ingredient/Spec Table, Supplement Facts Panel, Size Guide,
  Fit Finder, Colour/Variant Swatches, Variant Image Sync, Materials & Care,
  Dimensions & Weight, Comparison Table, How-To-Use Steps, Expandable FAQ Accordion
- **media** — Image Gallery with Zoom, Video on PDP, 360° Spin, Lifestyle Imagery,
  Before/After Imagery
- **trust** — Money-Back Guarantee, Warranty, Third-Party Testing/Certification,
  Made-In Claim, Clinical-Study Citation, Free Returns, Secure-Checkout Seal
- **fulfilment** — Delivery Estimate, Stock/Low-Stock Indicator, Back-in-Stock
  Notify, Store Pickup, COD Availability, Shipping Cost Calculator
- **personalisation** — Product Quiz/Finder, Recommended Add-Ons, Recently Viewed,
  Complete-the-Look, Flavour/Scent Selector
- **loyalty** — Rewards Programme, Referral Offer, Email/SMS Capture Offer,
  Membership Pricing
- **support** — Live Chat, WhatsApp Support, Contact/Help Link, Ask-a-Question CTA
- **content** — Editorial Story Block, Sustainability Claim, Founder/Brand Story,
  Blog/Journal Cross-Link

An agent that finds something genuinely absent from the list must add it under a
`"proposed_canonical"` key and say so in its report, not silently coin a synonym.

## Task 4 — Extract features: 13 parallel agents, one domain each

**Files:** each agent creates exactly one `data/pdp/raw/<domain>.json`.

Independent domains, no shared state, no shared files → textbook parallel
dispatch. Each agent's prompt carries: its domain, its markdown paths, the
canonical vocabulary verbatim, the JSON shape, and the four non-negotiable
evidence rules from `REQUIREMENTS.md` §3.

The one rule that decides whether this whole exercise works:

> `evidence` must be ONE contiguous run of text exactly as it appears in the
> DOM. Never join separate elements with `-`, `…`, `|` or `/`. A composite quote
> reads well and matches nothing. This caused a 7/19 match rate on JOOLA.

Each agent must also refuse to invent: markdown absence is not absence, and a
feature only visible in a URL slug gets `confidence ≤ 0.7` and a description
that says so.

**Step 1: dispatch 13 agents in a single message** (they run concurrently)

**Step 2: reconcile the canonical names**

```powershell
.venv\Scripts\python.exe scripts\query.py --canonical
```
Any near-duplicate pair is merged by editing the JSON and re-loading.

**Step 3: load every file**

```powershell
Get-ChildItem data\pdp\raw\*.json | ForEach-Object {
  .venv\Scripts\python.exe scripts\add_features.py $_.FullName
}
```

## Task 5 — Annotate: circle every feature on its own plate

**Step 1: run in batches of 3**

```powershell
.venv\Scripts\python.exe scripts\annotate.py --site <domain> --wait 4000
```

Thirteen concurrent Chromium instances at DPR 2 on a 20,000px page will thrash
the CPU and trip the 180s screenshot timeout — `annotate.py` says so in its own
comments. Three at a time.

**Step 2: read the output honestly**

`29/37 circled` is good. `BLOCKED` means **stop and wait, never loop**.
`0/N` means the evidence is wrong.

**Step 3: compare clean vs annotated plates — both size and brightness**

```powershell
Get-ChildItem data\screenshots\pdp\<domain>\*.png | Select-Object Name, Length
```

A timed popup landing between the two shots ruins only the annotated plate while
the run still prints a healthy count — GAMMA shipped nine solid-white crops that
way. Check mean brightness too, not just the count.

**Step 4: list and repair failures**

```powershell
.venv\Scripts\python.exe scripts\query.py --failed <domain>
```
Rewrite each failed `evidence` to a tighter contiguous string, re-load, re-annotate
that one site.

**Files:** Create `web/lib/pdp-db.ts`

A parallel read-only module pointed at `db/pdp.db`. It must repeat the
`plain()` row re-wrap — `node:sqlite` returns null-prototype rows and React

`pdpSites`, `pdpSite`, `pdpPages`, `pdpPage`, `pdpFeatures`, `pdpAnnotations`,
`pdpCategories`, `pdpMatrix`.

`pdpMatrix` is the view that answers the actual question — "what features do all
these PDPs have" — as canonical-slug rows × 13 domain columns.

Do **not** import from `web/lib/db.ts` and do not edit it.

## Politeness budget

These are 13 live third-party storefronts. Per domain the whole run is:
1 Firecrawl scrape + 1 crawl4ai scrape + 1 annotate pass (+1 re-annotate if
evidence needs repair) + at most 1 `verify.py` = **≤ 5 hits per domain, spaced**.
That is well inside the limit that tripped Cloudflare on joola.com (≈15 hits in
30 min to *one* domain). Different domains do not share a rate limit, so
batching across domains is safe; batching *within* one domain is not.
